# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Muscle Lab** is an exercise library web app in the "Night Session" design (dark, editorial, gold accent). The landing page lists every exercise in four category sections: Home Basics, Core Muscles, Extra Home Strength and Wrist Flexors (added 2026-10-27). Each exercise opens a detail page with an animated form guide, overview and tips, execution steps and the muscles it works. It works on laptop, iPad and phone, and can be added to an iPhone Home Screen.

It is a static site: no build step, no framework and no dependencies (Google Fonts only). It is deployed with GitHub Pages from the `main` branch root of https://github.com/assafhs-ship-it/muscle-lab, and the live site is https://assafhs-ship-it.github.io/muscle-lab/. To publish changes, commit and run `git push origin main`, **but only push when the user explicitly asks**. To preview locally, run `python3 -m http.server 8000` and open http://localhost:8000. Opening `index.html` directly also works.

`muscle-lab-claude-code-prompt.md` is the original design brief. It asked for React/Vite, but the app was built static because Node isn't installed and the other projects deploy to GitHub Pages without a build. The tokens, layout and behaviour follow the brief.

**When you change `css/*.css`, `js/app.js` or `data/exercises.js`, bump that file's `?v=` number in `index.html`.** GitHub Pages caches files for 10 minutes, and Safari can pair a new `index.html` with an old script.

## Files

- `index.html` contains the shell: the sticky header (brand and Home pill), an empty `<main>`, the floating Home button and an inline SVG icon sprite (`#i-house`, `#i-play`, `#i-pause`, `#i-left`, `#i-right`).
- `css/tokens.css` holds the design tokens (colours, fonts, fluid `clamp()` sizes, radii).
- `css/styles.css` holds the components, followed by breakpoints: tablet ≤1024px, phone ≤639px and ≤380px. It ends with a reduced-motion block.
- `data/exercises.js` is `window.EXERCISES = [...]`, the only content source. The array is plain JSON. It is a `.js` file rather than `.json` so the page also works when opened from the file system.
- `js/app.js` contains the hash router, landing and detail renderers, the `createAnimation` component and the wake lock.
- `tools/make_frames.py` builds every exercise image. Run `python3 tools/make_frames.py` (or name exercise ids, or `stills`) after source art changes. Its `EXERCISES` table lists each exercise's source frames in play order, and `STILLS` (now empty) can map single still images. Source art must be a figure on a plain blue background (gym-scene versions don't work; for the shoulder press use the blue `SPU1.jpg`/`SPU3.jpg`, not the gym PNGs). The script keys out the blue against each picture's own border colour (Guy1's background is darker), then aligns frames on the bottom 28% of the figure (bench legs, shins, shoes), so the man never changes size or position. It renders every frame onto the same "glossy white" backdrop the user chose (option B): white wall, pale floor, contact shadow, faded floor reflection and a highlight line. Figures cut off by the bottom of their picture (Guy1) get a plain white gradient with no floor. Wide poses (plank, pullover) get extra wall above them so the image is at least 0.8 as tall as it is wide (`MIN_ASPECT`); otherwise they fill the whole stage and look much bigger than the other exercises. Output is `assets/exercises/<id>/<n>.webp` and `assets/guy/guyN.webp`, max 1100px. Frames are shown with `object-fit: contain` and are never cropped. Bump the `?v=N` on an animation `src` in `exercises.js` whenever its images are regenerated.

- **Steady animations (`composite`, currently OFF via `COMPOSITE = False`)**: the user said it ruined some images and asked to revert it on 2026-10-22. Don't turn it back on without asking. How it worked: the artist redraws the bench and body slightly differently in every picture, so even aligned frames made still parts jitter. Every later frame is now frame 1 with only the moving region pasted in. `motion_mask` finds that region: alpha differences, plus strong colour changes (over 140, e.g. a dumbbell drawn over the bench leg). ## Architecture notes

- **Routing** is hash-based: `#/` for the landing page and `#/exercise/<id>` for a detail page. Hash routing keeps deep links working on GitHub Pages. `route()` destroys running animations and calls the previous page's detach function before rendering.
- **Animations**: `createAnimation(container, exercise, { playing, speed, onFrame })` picks a renderer from `renderers` based on `exercise.animation.type`. The types are `frames`, `image`, `video` and `placeholder` (used when `animation` is null). Each renderer returns `{ play, pause, setSpeed, goTo, frameCount, destroy }`. To support Lottie or another format, add a renderer. `frames` stacks all images and cross-fades them with a `setTimeout` loop. `fps * speed` sets the pace, unless the animation has `durations` (ms per frame at 1×, used to hold the top and bottom of a rep). The fade is about 55% of the frame time, capped at 380ms.
- **Categories**: each exercise has a `category`. Section headings use the "chapter" style the user chose (option A): a huge outlined gold number, a "Section NN · N exercises" line, and the name in gold, so they never look like the white exercise titles. `CATEGORIES` in `app.js` sets the section order. The main categories always show, with a dashed "No exercises yet" placeholder when empty. A category not in that list gets its own section after them, only while it has exercises. Each exercise keeps its body-area `group` for the card label and pills. Exercises are numbered within their own category (`positionInCategory`), both on the cards and in the "NN / NN" counter on the detail page; previous/next (the round arrows by the title, the larger Previous/Next cards at the bottom of the page, and the ←/→ keys) stay inside the exercise's own category and wrap around at its ends; they're hidden when a category has only one exercise. The current split is a placeholder the user will revise.
- **Category taglines**: `CATEGORY_TAGLINES` in `app.js` maps a category to `{ text, icon }` and shows it as a gold-outlined pill under the section heading. Text after the first ". " is shown in gold. Home Basics has "3 × 10. Simple, steady, strong." with the `counter` icon: a gold rep number counts 1–10 (`runCounter`, 170ms per rep), lights one of three set markers, repeats for three sets, rests, then loops. Core Muscles has "No counting. Just go until you drop." with the `pulse` icon, a beating heart-rate line. When a pill scrolls into view (IntersectionObserver adds `is-in`), its text blurs in, a light sweep crosses it, and a soft glow then pulses. Counters are stopped in the landing page's detach function. Reduced motion shows the pill static, with the counter at 10 and all three markers lit.
- **Category sources**: `CATEGORY_SOURCES` in `app.js` adds an optional video card under a section's tagline: a YouTube thumbnail with a gold play button, a "Source · Video" label, the title and the channel. It opens the link in a new tab. Core Muscles links to THENX's "6 Pack Abs For Beginners You Can Do Anywhere" and Extra Home Strength to Rob Riches' "Ten Great Bench & Dumbbell Exercises" (the user's playlist URLs, kept as given). The thumbnail is loaded from i.ytimg.com and removes itself if it fails to load.
- **Emblem**: `assets/guy/guy-general.webp` (from `Images/Guy/GuyGeneral.png`, a transparent cutout) is the landing page's mascot, not tied to any exercise. The user tried the full-body `GuyGeneral2.png` and chose to keep GuyGeneral. It sits in the hero's right column in front of a glowing gold disc with a slow-turning dashed orbit and a faint outlined "ASSAF" (was "LAB" until 2026-10-24). His legs fade out with a mask, and he floats gently. The hero grid areas are `copy emblem / credit emblem` on desktop and `copy / emblem / credit` at ≤1024px. When regenerating the webp, zero out alpha below ~16 *after* resizing; otherwise faint stray pixels show as a rectangle against the glow.
- **Creator credit**: under the hero copy, the page shows "Created by" and `CREATOR` from `app.js`, one word per line in the display font. Each word rises in on load (`word-rise`, staggered by `--i`), then a gold highlight sweeps across it on a loop (`shine`, done with `background-clip: text`). Reduced motion shows it static.
- **No playback controls**: the user removed the play/pause button, phase markers and speed buttons from every exercise (2026-10-24). `.stage__bottom` is hidden with CSS, animations always play at 1×, and the stage is 74px shorter (546px desktop, 352px phone) so pictures keep their size. The markup and `stage--still` class remain but have no visible effect. With reduced motion turned on, animations stay paused on frame 1.
- **Muscle maps**: an exercise with a `muscleMap` path gets a "Muscle map" section below the three info columns, showing a labelled picture with a Primary/Secondary colour key. The animation is unchanged. The pictures are built by `tools/make_muscle_maps.py` (style C, which the user chose): one animation frame, with the working muscles tinted red (primary) or blue (secondary; the user switched it from orange), plus underlined labels with pointer lines. Muscle regions are hand-drawn polygons in that frame's pixel coordinates, clipped to the skin, so they must be redrawn if the frame changes. All exercises have maps (Home Basics first, the rest added 2026-10-24 at the user's request). Muscles that aren't visible from the drawing's angle (e.g. glutes under shorts, upper traps) are left unlabelled. Per-map `scale` shrinks labels where space is tight.
- **Persisted preferences**: the landing scroll position (`muscle-lab:landing-scroll`) is saved in sessionStorage. Browser Back from a detail page restores the list position, while the Home buttons go to the top. All storage access goes through `store`, which swallows errors.
- **Reduced motion**: animations start paused and CSS transitions and animations are effectively disabled.
- **Wake lock**: while a detail animation plays, the screen stays awake, which helps between sets.
- **Keyboard**: on a detail page, ←/→ go to the previous/next exercise in the same category, and Space or K toggles play when focus isn't on a control.
- Each exercise still has a `level` in the data, but the site no longer shows it (the user removed the level tag and difficulty dots). In the muscle bars, Primary fills 100% and Secondary fills 55%.
- **Version**: `APP_VERSION` at the top of `js/app.js` is shown as "Version N" in the footer (`.site-footer__version`), next to "Muscle Lab by Assaf HS". It started at 1.0 on 2026-10-22; bump it (1.1, 1.2, …) with each pushed release. Don't select the footer with `[data-version]`: `<html>` also carries that attribute, and doing so once wiped the whole page.
- **Header**: the brand reads "MUSCLE LAB by Assaf HS", with "by Assaf HS" smaller and in gold (`.brand__by`).
